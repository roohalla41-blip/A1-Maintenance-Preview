# طرح جامع سامانه کنترل تعمیرات حساب صراف

## هدف و مرز
یک Control Plane مستقل برای اعلام وضعیت سرویس، مدیریت تعمیرات، اطلاع‌رسانی، اختلال محدود و بازگشایی کنترل‌شده. این مخزن فقط پیش‌نمایش استاتیک است؛ هیچ احراز هویت واقعی، توقف API، تغییر وضعیت سرور یا اتصال به A1 ندارد.

## نقش‌ها
- **سازنده اصلی:** اختیار نهایی شروع/پایان تعمیرات، مدیریت سیاست‌ها و تأیید بازگشایی.
- **مدیر عملیات:** ثبت رخداد، تنظیم ETA و انتشار اطلاعیه؛ بدون اختیار بازگشایی نهایی مگر با مجوز مستقل.
- **پشتیبانی:** مشاهده وضعیت، پاسخ‌گویی و ثبت گزارش؛ بدون تغییر حالت سامانه.
- **عمومی:** مشاهده وضعیت و اطلاعیه‌های عمومی.
اصل کمینه‌سازی دسترسی و کنترل مجوز در backend الزامی است.

## حالت‌های عملیاتی
1. عادی
2. تعمیرات کامل: اطلاعیه برای مشتری و صراف؛ سیاست توقف APIهای حساس باید سمت سرور اجرا شود.
3. اختلال محدود: فقط خدمات انتخاب‌شده محدود شوند.
4. اختلال اضطراری: اعلام سریع حادثه با دلیل، دامنه اثر و ثبت حسابرسی.
5. آماده بازگشایی: تعمیر تمام شده، اما سرویس هنوز عمومی نشده است.
6. بازگشایی: فقط پس از health checks، تطبیق عملیات و تأیید صریح سازنده.
7. 404: مسیر ناموجود و مستقل از وضعیت کلی سرویس.

## ماژول‌ها
- داشبورد عملیات و شاخص‌های سلامت
- کنترل وضعیت و انتقال‌های مجاز
- کاتالوگ خدمات و وابستگی‌ها
- اطلاعیه‌ها با مخاطب، زمان انتشار و تاریخچه
- زمان تخمینی (ETA) و پیام‌های عمومی
- بازیابی، چک‌لیست سلامت و تأیید بازگشایی
- رخدادها، شدت، دامنه اثر و مسئول پیگیری
- نقش‌ها، MFA، نشست‌ها و سیاست دسترسی
- گزارش حسابرسی: عامل، زمان، قبل/بعد، دلیل و نتیجه
- تنظیمات زبان، منطقه زمانی و کانال‌های اعلان

## قواعد حیاتی
- ETA فقط اطلاع‌رسانی است و هیچ‌گاه trigger بازگشایی نیست.
- «پایان تعمیرات» و «بازگشایی» دو مرحله مستقل‌اند.
- تعمیرات کامل در UI کافی نیست؛ API و jobهای مالی باید سمت سرور محدود شوند.
- عملیات مالی نیمه‌تمام باید idempotency و وضعیت قابل بازیابی داشته باشند.
- پیش از بازگشایی، صف عملیات معوق و تطبیق مالی بررسی شوند.
- هیچ پیام موفقیت مرورگر اثبات ثبت تراکنش نیست.
- هر اقدام حساس باید ثبت حسابرسی شود؛ 404 نباید redirect loop ایجاد کند.

## معماری پیشنهادی نسخه واقعی
- Public Status Web: صفحات وضعیت عمومی و اطلاعیه‌ها، بدون داده خصوصی.
- Admin Console: پنل سازنده و عملیات با MFA و نشست امن.
- Control API: اعتبارسنجی انتقال حالت، RBAC و ثبت audit اتمیک.
- Status Store: وضعیت جاری، نسخه‌ها، رخدادها و ETA.
- Service Registry: خدمات، وابستگی‌ها و سیاست degradation.
- Notification Dispatcher: ارسال از صف و ثبت نتیجه تحویل.
- Health Monitor: readiness checks و وضعیت صف‌های عملیاتی.
- Audit Ledger: رویدادهای append-only با دسترسی محدود.
- Integration Adapter: اتصال احتمالی به A1 فقط پس از بازبینی، تأیید و طرح بازگشت.

## امنیت و حفظ داده
هیچ secret، service-role key، رمز یا داده واقعی در مخزن preview یا browser storage. نسخه واقعی به MFA، RBAC سمت سرور، rate limiting، CSRF protection، انقضای نشست، backup و rollback نیاز دارد. تعمیرات نباید مستلزم حذف یا تغییر داده مالی باشد.

## معیار پذیرش
نمای مشتری و صراف متناسب باشد؛ اختلال محدود فقط خدمات انتخابی را تحت تأثیر قرار دهد؛ ETA منقضی‌شده بازگشایی خودکار نکند؛ بازگشایی بدون چک‌لیست و تأیید مجاز ممکن نباشد؛ همه تغییرات قابل ردیابی باشند؛ رابط روی موبایل و دسکتاپ درست کار کند.
